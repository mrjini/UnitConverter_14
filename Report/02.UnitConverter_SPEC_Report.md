## 1. STEP 1 — 주제 / 문제 정의

### 주제 (한 문장)

길이 단위 변환 CLI의 요구·검증·구현을 **PRD → To-Do → Test ID → Code**로 일대일 추적 가능하게 설계하고, Mom Test에서 드러난 **수동 재검증 비용**을 자동화된 테스트와 단일 변환 기준(meter 경유)으로 제거한다.

### Mom Test (가상 인터뷰)

| 구분 | 내용 |
|------|------|
| **표면 문제** | meter/feet/yard 길이 변환 CLI, 입력 형식 검증, 여러 출력 포맷 |
| **진짜 문제** | 변환값·검증 기준을 손·메모에만 두어 상수/규칙 변경 시 매번 처음부터 재확인하는 데 시간 소모 |
| **증거** | feet↔yard 직접 상수 → 40분 불일치 / 형식 검증 누락 / 리팩터 후 비교표 1시간+ 재작업 |

상세: [docs/process/mom-test-summary.md](../docs/process/mom-test-summary.md)

## 5. STEP 5 — 목표 아키텍처

### ECB (Entity–Control–Boundary + infrastructure)

**의존 방향:** `boundary → control → entity`  
**금지:** entity → 외부 레이어, control → boundary import

```
CLI → InputParser.parse() → (unit, value)
CLI → ConvertUseCase.execute(unit, value, registry) → Validator → Converter
CLI → Formatter → stdout
```

| 레이어 | 경로 | 책임 |
|--------|------|------|
| entity | `src/unit_converter/entity/` | Converter, Validator, UnitRegistry |
| control | `src/unit_converter/control/` | ConvertUseCase |
| boundary | `src/unit_converter/boundary/` | CLI, InputParser, Formatter |
| infrastructure | `src/unit_converter/infrastructure/` | ConfigLoader, UnitRegistrar |

### Dual-Track

| Track | Harness | Test |
|-------|---------|------|
| **Logic** (A) | `tests/entity/`, `tests/control/`, `test_input_parser.py` | CONV, VAL (예외 assert) |
| **UI** (B) | `tests/boundary/` | FMT, CLI-02~04, CFG, REG |

상세: [docs/spec/08-design-spec.md](../docs/spec/08-design-spec.md)
