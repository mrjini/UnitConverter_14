# Mom Test Summary (가상 인터뷰 요약)

> **면책:** 아래는 **가상 인터뷰** 결과이며, 실제 사용자 경험이 아님.

---

## 페르소나

길이 단위 변환 CLI를 구현하는 **학습자/개발자**

---

## 표면 문제

meter, feet, yard 길이 변환 CLI를 만들고, 입력 형식 검증과 여러 출력 형식까지 넣어야 한다.

---

## 진짜 문제 (한 문장)

여러 출처의 변환값을 손으로 맞춰 보고, 검증 기준을 머릿속·메모에만 두다 보니 상수나 입력 규칙을 바꿀 때마다 '맞는지'를 매번 처음부터 다시 확인하는 데 시간이 새는 것.

---

## Mom Test 증거 (3줄)

1. **과거 행동:** feet→yard를 meter 경유 없이 상수 두 개로 넣었다가, 테스트 기대값 불일치로 **40분** 뒤에야 손 대조로 원인을 찾음.
2. **실수 패턴:** 잘못된 입력 형식은 **처음 구현 때 검증하지 않았고**, 팀원 질문 후에야 추가함.
3. **확인 비용:** "맞다"는 판단을 엑셀·검색·코드 **수동 비교표**에 의존했고, 리팩터 후 **비교표를 처음부터 다시** 만들며 **1시간 이상** 재투입.

## 가상 인터뷰 3턴 (요약)

### Turn 1
검색·메모장·계산기 역산으로 feet/meter/yard 변환. 출처마다 소수 자릿수 달라 확인 필요.

### Turn 2
feet→yard 직접 상수 → 테스트 불일치 → **40분** 후 README와 손 대조로 meter 경유로 수정.

### Turn 3
엑셀 비교표로 검증. 형식 검증은 나중에 추가. 리팩터 후 비교표 **1시간+** 재작업.
